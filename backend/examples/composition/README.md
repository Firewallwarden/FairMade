# Synthetic composition examples

Merge passport-fragment.json with the existing required review_id/title/price
fields for an owned product's Passport draft. A replacement also needs its current
expected_revision. Data alone does not publish: preview, review the exact public
payload/hash, explicitly approve it, then separately activate the listing.
Use the current approved listing ID in normal buyer questions/saved scopes.

Replace seller-question.json's illustrative product ID with an owned product.
The optional source uses only recorded private recipe inputs and raw quantities;
it never infers finished contents or copies a recipe into public declarations.
The same option works in saved seller scopes. Ask a follow-up about why input
evidence does not prove final ingredients or safety.

Examples are synthetic declarations, not real recipe or safety claims. Render
roles/specifications as untrusted text and exact quantities as separate facts.
See [the contract and frontend handoff](../../../docs/composition-explanations.md).
